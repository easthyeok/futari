# 음식과 데이트 고르기

## 음식 후보

`food.js`에 14종류 × 26개, 총 364개의 중복 없는 음식과 개별 조합 설명을 보관합니다. 이름·분류·설명을 검색할 수 있습니다. ‘떡볶이’의 당면·치즈 추가나 ‘샤브샤브’의 얼큰한 국물·맑은 국물처럼 먹고 싶은 스타일과 곁들임을 제안하며 조리 절차·시간은 표시하지 않습니다.

- 한식, 국물·찌개, 고기구이, 해산물, 면, 밥·덮밥, 분식, 중식, 일식, 양식, 아시아·세계요리, 가벼운 식사, 간편식·빵, 야식·안주.
- 한 번에 최대 6개를 무작위로 보여줍니다. 섞은 후보를 모두 소진한 다음 새로 섞고, 한 화면 안에서는 중복되지 않습니다. 필터를 바꾸면 새 후보 목록으로 다시 섞습니다.
- 저장한 음식 3개가 추천 앞자리를 계속 차지하던 동작을 제거했습니다. ‘다음에 먹자’로 모은 목록은 별도로 유지합니다.
- 최근 먹은 음식 제외는 완료 표시한 기록 중 마지막 12개를 기준으로 합니다. 새 완료 기록에는 `eatenAt`을 남기고 기존 완료 데이터도 지원합니다. 체크를 해제하면 다시 포함합니다.
- 전체 메뉴 목록은 접어서 제공하고 펼친 목록 안에서 스크롤합니다. 직접 추가한 이름·조합도 저장 목록과 후보에 포함하며 ‘우리 메뉴’ 분류로 찾을 수 있습니다.
- 새 음식 저장 형식은 `{id,name,description,done}`입니다. 기존 `reason`·`preparation` 데이터는 삭제하지 않습니다. 기존 음식은 일치하는 로컬 조합 설명을 우선 표시하고 조리법은 표시하지 않습니다.

## 데이트 후보

미완료 버킷과 저장한 장소를 12가지 기본 코스에 합쳐 섞습니다. 코스에는 설명과 활동 순서를 표시합니다. 음식 목록과 데이트 목록을 별도로 관리하고, 데이트 탭에는 저장한 음식을 표시하지 않습니다.

## AI 제거

클라이언트는 외부 추천 API를 호출하지 않고 기록을 전송하지 않습니다. `FOOD_AI_ENABLED` 설정과 Gemini 프롬프트·쿼터 처리·환경 변수 예시를 제거했습니다. 이미 설치된 예전 앱의 호출도 차단하기 위해 `food-recommend-gemini` 서버 함수는 `410 {"error":"ai_removed"}`만 반환합니다. 사용량 DB와 기존 마이그레이션은 데이터 보존을 위해 그대로 두며 더 이상 추천에 사용하지 않습니다.

일반적인 방 기록 저장·동기화는 기존 Supabase 연결을 사용합니다. 서버 함수는 새 버전으로 별도 배포해야 예전 클라이언트의 AI 호출까지 중단됩니다. 화면은 GitHub Pages 코드 배포와 설치된 앱의 셸 업데이트가 필요합니다.
