# 음식 고르기

## 간단한 홈 화면

처음에는 ‘오늘 뭐 먹지?’ 버튼만 표시합니다. 누르면 음식 4개와 최대 72자의 짧은 조합 설명, 음식별 ‘다음에 먹자’ 버튼과 네 후보를 바꾸는 ‘다른 메뉴’ 버튼이 펼쳐집니다. 홈 버튼을 다시 누르거나 Escape 키로 닫습니다. 검색·필터·전체 목록·직접 추가·저장 목록을 이 화면에서 제거했습니다.

## 음식 후보와 저장

- `food.js`의 14종류 × 26개, 총 364개의 음식과 개별 조합 설명을 유지합니다. 조리 절차·시간은 표시하지 않습니다.
- 섞은 후보에서 한 번에 4개씩 꺼내며 한 바퀴 소진한 뒤 다시 섞습니다. 접었다 열어도 현재 화면의 덱을 이어서 사용합니다.
- ‘먹었어’로 표시한 최근 12개는 자동 제외합니다. 메뉴 선택 전에 설명과 후보 목록을 미리 펼치거나 서버에 요청하지 않습니다.
- ‘다음에 먹자’는 `{id,name,description,done:false}`로 저장합니다. 같은 미완료 메뉴를 중복 저장하지 않으며, 저장 후에도 현재 메뉴를 유지합니다.
- 기존 음식 기록과 직접 추가했던 후보·완료 여부는 보존합니다. 방을 바꾸면 이전 방에서 펼쳤던 메뉴를 보여주지 않습니다.

## 데이트 코스 추천 제거

음식 화면의 데이트 탭·기본 코스·추천 생성·버킷 저장 기능은 제거했습니다. 이미 저장된 일정·장소·버킷 데이터는 삭제하거나 변경하지 않습니다.

## AI 제거

클라이언트는 외부 추천 API를 호출하지 않고 기록을 전송하지 않습니다. `FOOD_AI_ENABLED` 설정과 Gemini 프롬프트·쿼터 처리·환경 변수 예시를 제거했습니다. 이미 설치된 예전 앱의 호출도 차단하기 위해 `food-recommend-gemini` 서버 함수는 `410 {"error":"ai_removed"}`만 반환합니다. 사용량 DB와 기존 마이그레이션은 데이터 보존을 위해 그대로 두며 더 이상 추천에 사용하지 않습니다.

일반적인 방 기록 저장·동기화는 기존 Supabase 연결을 사용합니다. 서버 함수는 새 버전으로 별도 배포해야 예전 클라이언트의 AI 호출까지 중단됩니다. 화면은 GitHub Pages 코드 배포와 설치된 앱의 셸 업데이트가 필요합니다.


카탈로그 개수·유일성·개별 설명, 버튼만 있는 초기 화면, 음식 4개 표시·짧은 설명, 후보 전체 소진 전 중복 방지, 최근 먹은 메뉴 제외, 중복 저장 방지·기존 기록 보존, 접기·Escape, 데이트 추천 제거, 방 전환, 네트워크 없이 사용, 예전 서버 경로의 AI 호출 차단을 검사합니다. 브라우저 레이아웃·설치된 PWA 업데이트는 실제 기기 검증이 별도로 필요합니다.
