# futari 💑

두 사람이 한 생명체를 함께 돌보고, 진화시키고, 새로운 알을 발견하는 커플 웹앱입니다. 빌드 없이 정적 웹 서버에서 실행합니다.

## 현재 화면

| 탭 | 내용 |
|----|------|
| 🏡 우리의 지금 | 하고 싶은 일 추천·날짜 정하기, 오늘의 기분, 지난 기록 다시 보기, 다가오는 날, 게임 바로가기 |
| 💛 오늘 우리 | 기분, 30개 주제의 발견·상상 카드, 오늘의 질문, 함께한 시간 |
| 📅 우리의 날들 | 제목·사진이 보이는 기록 달력, 그날의 일기, 검색, 버킷리스트 |
| 🎲 보드게임 | 오목, 총알 피하기 기록 대결 |
| 상단 메뉴 | 편지, 기존 추억, 알림, 설정·백업 |

마을·농사·집 꾸미기는 화면에서 제거했습니다. 이전 모듈은 저장 데이터의 경제 계산과 호환성 검증을 위해 남겨두며 메인에서 진입하지 않습니다. 기존 가구·작물·사진·일정은 백업에 보존합니다. 작물 알림과 예전 마을 활동 알림은 표시하지 않습니다.

## 우리의 날들: 기록 달력

약속을 잡는 화면 대신, 날짜별로 함께 보낸 날을 읽고 기록합니다. 달력 날짜 칸에는 제목과 사진 썸네일이 나오고, 날짜를 누르면 제목·사진·본문이 펼쳐집니다. 월 선택과 제목·본문·장소·지난 회고 검색을 지원합니다. 검색 결과를 누르면 그날로 이동합니다.

기록 입력은 날짜·제목·본문·사진(새 첨부 최대 6장)입니다. 제목만 저장할 수도 있습니다. 본문 줄바꿈을 유지하며 사진은 눌러 크게 보고 넘길 수 있습니다. 사진은 파일당 8MB 이하, 긴 변 960px JPEG로 압축합니다. 업로드 실패 시 작성 중인 글은 유지합니다. 시간·반복·알림·만족도 입력은 기록 화면에서 제외했습니다.

새 기록은 기존 `memories`에 저장합니다. 기존 `dates`와 `memories`는 이동하거나 삭제하지 않고 함께 표시합니다. 연결된 일정·추억은 한 카드로 묶어 메모와 사진을 합쳐 보여주며, 원래 회고는 펼쳐 볼 수 있습니다. 기존 기록을 수정하면 원본 항목의 알 수 없는 필드와 반복 설정 등은 보존합니다. 반복 일정은 실제로 기록된 시작 날짜에서만 보여주며 미래의 추억을 자동 생성하지 않습니다. 기록 수정 뒤 `journalEdited`로 저장한 본문·사진을 우선 표시하며 연결된 원본 추억도 백업에는 보존합니다.

스타일은 `journal.css`, 일기 표시·저장 로직은 `calendar.js`입니다. `tests/journal-calendar.cjs`에서 기존 기록 보존, 중복 표시 방지, 검색, 사진·줄바꿈·수정, 업로드 실패, 중복 저장, 두 사용자 기록 병합을 확인합니다.

## 우리의 지금과 오늘 우리

첫 화면은 반복 돌봄 대신 둘의 실제 기록과 다음 활동을 연결합니다. 미완료인 하고 싶은 일에서 하나를 추천하고 다른 아이디어를 고르거나 날짜를 정할 수 있습니다. 지난 기록 하나를 사진·본문과 함께 다시 보여주며, 다가오는 기록과 오늘 우리·게임으로 이동합니다. 기존 육성 데이터와 모듈은 보존하며 메인에서는 진입하지 않습니다.

오늘 우리는 여행·음식 3일 반복 대신 응원, 습관, 상상, 취미 등 30개 주제를 날짜에 따라 두 카드로 보여줍니다. 각 카드 주제는 30일 주기로 순환하며 두 카드의 주제는 서로 다릅니다. 기존 `travel`·`food` 답변은 보존하고 새 답변은 `moment`·`imagine`에 저장합니다. 두 사람이 선택한 뒤 결과를 함께 공개하며 기존 공동 저장과 보상 계산을 유지합니다. 참여를 강요하는 코인 안내 대신 대화를 중심으로 표시합니다.

## 생명체 육성 (이전 구현 보존)

- 기본 알은 숲(새잎콩), 물(물방울), 별(별먼지)입니다. 현재 친구의 최종 성장 뒤 다음 알을 고릅니다.
- 마음 8에 부화, 28에 성장기, 60에 최종 진화합니다. 쉬어도 성장치는 줄지 않습니다.
- 각자 하루 방문 +1, 간식 +3, 놀이 +2. 둘 다 방문하면 공동 +2. 방문 기록이 있는 날의 기분·질문 답변은 각각 +2입니다. 같은 날 같은 행동은 중복 보상하지 않습니다.
- 딸기와 달빛 우유 중 더 많이 먹은 먹이에 따라 최종 모습이 갈립니다. 동률은 딸기 쪽입니다. 최종 성장 뒤 먹이·놀이는 마감하지만 옷은 계속 바꿀 수 있습니다.
- 다 큰 친구 두 마리로 특별한 알을 발견합니다. 친구는 소모하지 않습니다. 숲+물 → 연꽃, 물+별 → 오로라, 숲+별 → 해바라기, 오로라+연꽃 → 꿈의 정령. 각 히든 계열도 최종 모습이 두 가지입니다.
- 기본 알은 반복 육성할 수 있습니다. 옷은 성장 완료 친구 수 0/1/3/5에 따라 열리며 무료입니다. 이전 코인 기록은 보존합니다.
- 독창적인 SVG 캐릭터를 코드로 그립니다. 단계별 외형, 먹이에 따른 최종 색상, 기분 표정, 공동 방문 동작과 동작 줄이기 설정을 지원합니다.

공동 데이터 `creatures`는 `active`와 ID별 `pets`를 저장합니다. 친구마다 종, 시작 날짜, 부모 ID, 옷, 날짜·사용자별 돌봄 기록을 저장하고 성장치는 기록에서 계산합니다. 기존 CAS/outbox 저장과 복구를 사용하며 두 사람의 독립 돌봄은 병합합니다. 같은 알이나 옷을 동시에 다르게 선택하는 충돌은 기존 복구 안내로 처리합니다. 사용자 선택은 인증을 대신하지 않습니다.

새 파일: `creatures.js`(육성 규칙·SVG·화면), `creatures.css`(메인 스타일), `tests/creatures.cjs`(성장·조합·동시 저장·상호작용 검증). `home.js`는 이전 보상 계산과 메인 연결을 유지합니다.

아래 실행·설치·동기화 설명은 계속 적용됩니다. 하단 마을·실내 기능 설명은 **이전 구현의 보존·복구 참고 자료**이며 현재 화면에서는 제공하지 않습니다.

## 실행

```sh
python3 -m http.server 8000
```

서버가 출력하는 주소로 접속하세요. React와 Supabase 클라이언트는 `vendor/`에 포함되어 있습니다.
공유 저장에는 인터넷 연결 및 `config.js`의 Supabase 연결 설정이 필요합니다. 지도 SDK와 지도 API 키는 사용하지 않습니다.

## PWA 설치와 GitHub Pages

배포 주소: https://easthyeok.github.io/futari/

`manifest.webmanifest`에 앱 이름, 192/512px PNG 아이콘, `standalone` 표시 모드와 시작 경로를 정의했습니다. 모든 경로는 상대 경로여서 `/futari/`에 배포할 수 있습니다. 실제 배포 서버의 응답과 브라우저 설치 판정은 별도로 확인해야 합니다.

- HTTPS 주소를 크롬에서 직접 여세요. 카톡 등의 앱 내부 브라우저 대신 크롬을 사용하세요.
- 설치 가능한 상태가 되면 화면 상단의 ‘앱 설치’를 누르거나 크롬 메뉴에서 ‘앱 설치 / 홈 화면에 추가’를 선택하세요. 설치 안내가 바로 나타나는 시점은 브라우저 상태와 사용 이력에 따라 달라집니다.
- iPhone·iPad Safari에서는 설치 안내 팝업을 자동 표시합니다. 공유 → 홈 화면에 추가 → 추가 순서로 진행하며, ‘웹 앱으로 열기’가 보이면 켭니다. Safari는 웹에서 네이티브 설치 창을 직접 호출할 수 없어 안내 팝업을 사용합니다.
- 안내를 닫으면 같은 탭 세션에서는 다시 자동 표시하지 않습니다. 상단 ‘앱 설치 안내’에서 언제든 다시 열 수 있고, 홈 화면에서 앱으로 실행 중이면 안내하지 않습니다. 데스크톱 모드 iPad도 감지하며 Mac Safari에는 Dock에 추가 방법을 안내합니다.
- 개발용 `http://localhost:8000`은 서비스 워커를 사용할 수 있지만 휴대폰에서 PC의 `http://192.168…` 주소로 접속하면 보안 연결 요건을 충족하지 못합니다.

Chrome DevTools → Application에서 Manifest의 아이콘·시작 주소·오류와 Service Workers의 활성 상태를 확인하세요. Network의 Offline을 켜고 새로고침하여 화면이 열리는지 확인하세요. 매니페스트와 아이콘 URL이 HTML 오류 페이지 대신 실제 JSON/PNG로 응답해야 합니다.

서비스 워커는 온라인에서는 앱 파일을 서버에 다시 확인하고, 연결 실패 시 최근 파일을 사용합니다. 캐시 버전 변경을 빠뜨려도 온라인 재접속으로 파일이 갱신됩니다. 서비스 워커는 앱 파일만 캐시하며 Supabase 요청과 방 코드가 담긴 URL을 캐시하지 않습니다. 앱의 방 데이터는 기존처럼 방별 localStorage에 보관합니다. 앱 화면이 바뀌면 `sw.js`의 `CACHE_NAME` 버전을 올리세요. 새 버전이 대기하면 상단에 ‘업데이트’ 버튼을 표시합니다. 현재 변경이 저장된 뒤 버튼을 눌러 새 버전으로 다시 열 수 있습니다. 편집 도중 강제로 새로고침하지 않습니다. 업데이트 버튼이 없는 이전 버전에서 화면이 바뀌지 않으면 아래 복구 페이지를 사용하세요. 브라우저 데이터나 localStorage를 지우지 않아도 됩니다.

### 이전 화면이 계속 보일 때

배포 완료 후 크롬에서 https://easthyeok.github.io/futari/recover.html 을 열어 ‘최신 화면 다시 받기’를 누르세요. 이 페이지는 이전 서비스 워커의 캐시 대상이 아니므로 오래된 앱에서도 새 복구 페이지를 받을 수 있습니다. 다른 futari 탭과 앱 창을 닫고 진행한 뒤 ‘futari 다시 열기’를 누르세요.

복구는 최신 앱 파일을 모두 다운로드하고 배포 버전을 확인한 다음 기존 앱 캐시의 파일을 교체합니다. 방 코드·사용자 선택·localStorage·추억·공유 보드게임 데이터는 삭제하지 않습니다. 미저장 변경이 있으면 복구를 중단하며, 다운로드 실패나 이전 배포가 응답하는 경우에는 기존 캐시를 유지합니다.

설정에서도 ‘이전 화면이 보일 때 새로 받기’로 복구 페이지에 갈 수 있습니다. 페이지가 404이면 해당 파일의 커밋·푸시와 GitHub Pages 배포 완료를 먼저 확인하세요.

## 둘이 보드게임

하단의 독립 보드게임 탭에서 게임을 선택하세요. 게임룸은 게임판 중심 화면, 전체 화면(지원 브라우저), 경기 전적과 최근 결과를 제공합니다. 사목·주사위 레이스·카드 덱은 제거했습니다.

### 오목 · 각자 기기에서 이어하기

15×15 자유 오목입니다. 금수 없이 가로·세로·대각선으로 5개 이상 이으면 승리합니다. 작은 화면에서 실수로 두지 않도록 칸을 선택한 뒤 확인 버튼으로 착수합니다. 판 확대, 좌표, 수 번호, 대국 복기를 지원합니다. 마지막 수는 둔 사람이 요청하고 상대가 동의해야 되돌릴 수 있습니다. 새 경기의 검은 돌·선공은 번갈아 바뀝니다.

오목은 시간제한 없이 방에 저장되어 각자 기기에서 이어합니다. 무르기와 새 판은 상대의 동의가 필요합니다. 다빈치코드와 바운스오프는 제거했으며 기존 백업 속 기록은 보존합니다.

### 총알 피하기 / NEON DRIFT

게임룸에서 총알 피하기를 엽니다. 모바일은 화면 어느 위치에서든 상대적으로 드래그해 기체를 움직이고, PC는 방향키 또는 WASD, Shift로 정밀 이동합니다. 흰 중심점만 피격 판정하며 18초마다 탄막이 강화되고 90초를 버티면 완주합니다. 탄막 예고·근접 회피·효과음 선택을 제공합니다.

연습은 무제한이며 일시정지할 수 있습니다. 실전은 기기 현지 날짜 기준 각자 하루 3번, 최고 생존 시간으로 비교합니다. 같은 날짜·버전은 같은 난수 시드와 고정 시간 간격을 사용합니다. 조준 탄막의 방향은 각자의 이동 위치에 따라 달라집니다. 실전은 시작 시 횟수를 사용하고, 화면 전환·앱 이탈 시 현재 기록으로 종료합니다. 새로고침·비정상 종료 후 남은 예약은 0초로 처리합니다. 기록은 방의 `dodge`에 저장되어 상대 기기와 동기화하며 최근 7일과 역대 최고 기록을 확인할 수 있습니다. 게임 중에는 네트워크 응답을 기다리지 않습니다.

승부는 소수점 둘째 자리까지의 생존 시간만 비교하고 근접 회피 횟수는 승패에 영향을 주지 않습니다. 실전 기록은 기존 방 데이터와 같은 저장 실패·충돌 보호를 따릅니다. 현재 기록은 클라이언트에서 계산하며 서버가 검증하는 대회용 기록은 아닙니다.

### 농장처럼 키우는 우리 마을

메인 화면의 빈 땅을 골라 텃밭·꽃밭·피크닉 자리·사과나무·연못·작업실·온실을 짓습니다. 건설은 현재 잔액을 검사하고 이미 지은 자리에 중복 구매할 수 없습니다. 건물은 무료로 이동·서로 교환할 수 있으며 재배 중인 작물도 함께 이동합니다.

텃밭과 온실에서는 씨앗을 구매해 재배합니다. 래디시 60초, 당근 180초, 딸기 360초이며 온실에서는 두 배 빨리 자랍니다. 각자 한 번 물을 주면 15초씩 단축됩니다. 둘이 물 준 작물은 수확 시 1코인을 추가로 받습니다. 다 자란 작물은 수확하면 코인이 지급되고, 오랫동안 접속하지 않아도 시들지 않습니다. 중복 수확은 보상하지 않습니다.

집은 오두막 → 농가 → 전원주택 → 꿈꾸던 집의 4단계이며 땅도 4 → 8 → 12 → 16칸으로 늘어납니다. 확장에는 코인과 함께 쌓은 마음이 필요합니다. 집을 누르거나 ‘집 안 꾸미기’에서 기존 가구와 추가 가구·벽지·바닥을 구매·배치할 수 있습니다. 실내 가구와 농장은 같은 지갑을 사용합니다. 마을 상태는 `farm`, 실내 소유·배치는 `house`에 저장되어 방 동기화와 백업에 포함됩니다.

오목은 하루 첫 완료에 15 코인을 받습니다. 같은 날 재대결은 중복 보상하지 않습니다. 오늘 우리 카드와 기존 활동에서 얻는 코인, 작물 수확 수입에서 실제 가구·건설·씨앗·확장 비용을 차감해 공동 잔액을 계산합니다.

기존 장소 기록은 백업 호환성을 위해 보존되지만 지도 화면은 제거했습니다.

## 활동 알림과 동기화

상단 종에서 상대의 일정·질문·기분·재배·가구·집 확장·위시리스트·게임·우편 활동을 확인합니다. 알림과 실제 변경은 같은 `rooms.data` 저장에 포함하고, UI는 서버에서 확인된 스냅샷만 표시합니다. 본인 활동은 본인 알림에서 제외합니다. 읽음 상태는 `notificationReads.me/you`에 분리하며 반복 활동은 묶습니다. 알림을 누르면 해당 화면과 일정·텃밭·편지로 이동합니다.

변경은 약 250ms 뒤 순서대로 저장합니다. Supabase Realtime Postgres Changes에 구독하고, 구독 연결·온라인 복귀·앱 포커스 때 다시 조회합니다. Realtime이 비활성화되어도 5초 정기 조회로 보완합니다. 서버의 `updated_at`을 비교하는 CAS 저장과 기기의 작업 ID/변경 목록 `outbox`를 사용합니다. 서버의 `commits`에 이미 있는 작업은 재실행하지 않아 응답 유실 뒤 재시도로 인한 중복 비용·보상을 방지합니다. 서로 다른 항목, 두 사람의 물주기·동물 돌봄은 자동 병합합니다.

같은 제목을 서로 다르게 수정하거나 같은 작물을 동시에 수확하는 등 양립할 수 없는 변경은 자동 덮어쓰기하지 않습니다. 미저장 변경과 기준 데이터는 기기에 보관하고 오류를 표시합니다. ‘상대 변경 불러오기’는 현재 미저장 변경을 먼저 복구용 백업으로 보관합니다. 공동 지갑은 병합 후에도 음수가 되지 않도록 검사합니다.

스키마 버전은 2입니다. 기존 커플 정보·기념일·사진·일정·작물의 성장 시각·경제 카운터·건물·가구·게임 기록과 알 수 없는 일반 필드를 유지합니다. 마이그레이션 전에 방별 원본 백업을 로컬 저장소에 남기며 백업 실패나 미래 버전 데이터는 변경을 중단합니다. 설정에서 복구용 백업을 내려받을 수 있습니다. 개발 전에 현재 방의 백업 내보내기를 별도 파일로 보관하세요. 브라우저 저장소만으로 독립적인 서버 백업을 대신할 수는 없습니다.

알림은 앱 내부 기능입니다. 일정별 시간 알림과 작물 성장 완료 알림은 앱이 열려 있을 때 생성됩니다. 앱 종료 상태의 OS 푸시는 아직 구현하지 않았으며 서비스 워커 Push API·구독 DB·서버 발송·권한 요청을 별도 구성해야 합니다.

보안과 운영 절차는 [SECURITY.md](docs/SECURITY.md), 구현/마이그레이션 설명은 [UPGRADE.md](docs/UPGRADE.md), 검증 범위는 [VALIDATION.md](docs/VALIDATION.md)를 확인하세요. 현재 사용자 선택과 방 코드는 인증이 아닙니다. 운영 RLS 정책은 별도 확인이 필요합니다.

## 새 캘린더와 공동 콘텐츠

따뜻한 월간·주간 달력, 일정 종류별 색상, 날짜 길게 누르기·좌우 이동, 시간·장소·메모·종일·반복·앱 내부 알림을 제공합니다. 일정은 등록 즉시 공동 캘린더에 표시합니다. **데이트 제안·수락 절차는 사용자의 후속 요청에 따라 제외했습니다.** 반복 일정 편집은 전체 시리즈에 적용하며 월말과 윤일은 존재하는 날짜에만 표시합니다. 지난 일정에는 개인별 회고·만족도·사진(최대 3장)을 추가하고 기존 추억 사진을 유지합니다.

위시리스트에서 날짜를 정하면 바로 캘린더 일정이 됩니다. 우편함에서는 짧은 편지와 읽음 여부를 공유합니다. 하루 작은 미션 2개(기분 나누기·서로 편지 보내기)는 각각 공동 보상 2코인이며 연속 참여를 강제하지 않습니다. 도감은 작물·동물·가구·기존 추억·활동 업적을 모아 보여줍니다.

## 마을과 자유 배치

마을 그래픽은 직접 작성한 Canvas/SVG 일러스트이며 외부 이미지나 스프라이트를 사용하지 않습니다. 계절·낮밤·구름·물결, 좌표 기반으로 움직이는 오리·고양이·강아지·토끼를 표시합니다. 동물은 Idle/Walk/Sleep/Interact/Special 상태를 가지며 터치, 이름, 하루 각자 한 번 간식, 호감도·공동 돌봄 기록을 제공합니다. 건물 장애물을 피하고 화면 밖/백그라운드에서는 렌더링을 중지합니다. 질병·사망·불참 페널티는 없습니다.

작물은 저장된 시각으로 씨앗·새싹·성장·수확 가능 단계를 계산합니다. 토마토·해바라기를 추가하고, 둘이 물 준 수확은 1코인만 추가합니다. 해바라기 3회 수확으로 특별 꽃다발을 얻습니다. 물주기·수확 연출은 성장 시간과 분리합니다.

실내 가구는 격자에 자유 배치하고 회전·미리보기·이동·보관할 수 있습니다. 가구 충돌과 벽/바닥/카펫 레이어를 검사하고 집 확장에 따라 방 크기가 늘어납니다. 기존 구매와 고정 배치는 보존하며 자유 배치 첫 저장 때 위치를 변환합니다. 두 캐릭터의 색·머리/모자 선택과 소파·침대에서 쉬는 동작을 제공합니다.

### 기기 백업 공간과 사진 압축 (2026-10-15)

일반 자동 저장은 현재 캐시를 원자적으로 교체하며 매번 전체 이력 백업을 만들지 않습니다. 기존 `futari_recovery_snapshot_` 백업은 앱 시작 때 IndexedDB의 `futari-recovery/snapshots`로 옮깁니다. 트랜잭션 완료 후 원본이 동일한 항목만 localStorage에서 제거하고, 이전 백업은 읽기 전용 복구 화면의 원본 백업 다운로드에 포함합니다. IndexedDB를 사용할 수 없거나 이관에 실패하면 기존 백업은 유지됩니다.

회고 사진은 원본 최대 40MB를 받아 긴 변 최대 1280px, JPEG 파일 기준 장당 200KB 이하로 자동 압축합니다. 품질 조정 후 필요하면 해상도를 더 줄이며 현재 기록 편집기의 최대 6장을 순차 처리합니다. DB에는 여전히 Base64로 저장되므로 사진당 약 267KB와 JSON 오버헤드가 발생하고 회고/추억 양쪽에 포함될 수 있습니다. 기존 사진은 자동 변경하지 않습니다. 대량 사진의 장기 보관에는 별도 객체 저장소 도입이 필요합니다.
