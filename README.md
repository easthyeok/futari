# futari 💑

선택과 반응으로 둘만의 집과 추억을 쌓는 웹앱입니다. 빌드 없이 정적 웹 서버에서 실행합니다.

## 기능

| 탭 | 내용 |
|----|------|
| 🏡 우리 마을 | 건설·재배·수확·집 확장·실내 꾸미기 |
| 💛 오늘 우리 | 기분, 같이 떠난다면, 먹고 싶은 것, 오늘의 질문카드 |
| 📅 약속 | 약속·달력, 버킷리스트 |
| 🎲 보드게임 | 오목, 총알 피하기 기록 대결, 경기 전적 |
| ⚙️ 상단 설정 | 사용자 변경, 이름·기념일, 초대 링크, 백업 |

각 기기에서 처음 한 번 자신의 이름을 선택합니다. 오늘의 카드는 자기 기기에서 본인의 선택과 답변만 남깁니다. 둘 다 참여하면 여행·음식 취향과 질문 답변을 함께 공개합니다. 기분·여행·음식·질문 참여는 각자 3 코인씩, 네 가지를 둘 다 마치면 공동 보너스 12 코인을 받습니다. 답변 수정·반복 클릭은 추가 보상하지 않습니다. 기존 활동 보상과 구매한 가구는 유지합니다.

추억 탭은 제거했습니다. 기존 추억과 사진 데이터는 삭제하지 않고 백업 내보내기에 포함합니다. 자동 기록을 포함한 과거 데이터와 약속·버킷리스트는 유지합니다. 사용자 선택은 인증을 대신하지 않습니다.

## 실행

```sh
python3 -m http.server 8000
```

서버가 출력하는 주소로 접속하세요. React와 Supabase 클라이언트는 `vendor/`에 포함되어 있습니다.
공유 저장에는 인터넷 연결 및 `config.js`의 Supabase 연결 설정이 필요합니다. 지도 SDK와 지도 API 키는 사용하지 않습니다.

## PWA 설치와 GitHub Pages

배포 주소: https://easthyeok.github.io/futari/

`manifest.webmanifest`에 앱 이름, 192/512px PNG 아이콘, `standalone` 표시 모드와 시작 경로를 정의했습니다. 모든 경로는 상대 경로여서 `/futari/`에 배포할 수 있습니다. 실제 배포 서버의 응답과 브라우저 설치 판정은 별도로 확인해야 합니다.

- HTTPS 주소를 크롬에서 직접 여세요. 카톡 등의 앱 내부 브라우저 대신 크롬을 사용하세요.
- 설치 가능한 상태가 되면 화면 상단의 ‘앱 설치’를 누르거나 크롬 메뉴에서 ‘앱 설치 / 홈 화면에 추가’를 선택하세요. 설치 안내가 바로 나타나는 시점은 브라우저 상태와 사용 이력에 따라 달라집니다.
- iPhone·iPad Safari에서는 설치 안내 팝업을 자동 표시합니다. 공유 → 홈 화면에 추가 → 추가 순서로 진행하며, ‘웹 앱으로 열기’가 보이면 켭니다. Safari는 웹에서 네이티브 설치 창을 직접 호출할 수 없어 안내 팝업을 사용합니다.
- 안내를 닫으면 같은 탭 세션에서는 다시 자동 표시하지 않습니다. 상단 ‘앱 설치 안내’에서 언제든 다시 열 수 있고, 홈 화면에서 앱으로 실행 중이면 안내하지 않습니다. 데스크톱 모드 iPad도 감지하며 Mac Safari에는 Dock에 추가 방법을 안내합니다.
- 개발용 `http://localhost:8000`은 서비스 워커를 사용할 수 있지만 휴대폰에서 PC의 `http://192.168…` 주소로 접속하면 보안 연결 요건을 충족하지 못합니다.

Chrome DevTools → Application에서 Manifest의 아이콘·시작 주소·오류와 Service Workers의 활성 상태를 확인하세요. Network의 Offline을 켜고 새로고침하여 화면이 열리는지 확인하세요. 매니페스트와 아이콘 URL이 HTML 오류 페이지 대신 실제 JSON/PNG로 응답해야 합니다.

서비스 워커는 온라인에서는 앱 파일을 서버에 다시 확인하고, 연결 실패 시 최근 파일을 사용합니다. 캐시 버전 변경을 빠뜨려도 온라인 재접속으로 파일이 갱신됩니다. 서비스 워커는 앱 파일만 캐시하며 Supabase 요청과 방 코드가 담긴 URL을 캐시하지 않습니다. 앱의 방 데이터는 기존처럼 방별 localStorage에 보관합니다. 앱 화면이 바뀌면 `sw.js`의 `CACHE_NAME` 버전을 올리세요. 새 버전이 대기하면 상단에 ‘업데이트’ 버튼을 표시합니다. 현재 변경이 저장된 뒤 버튼을 눌러 새 버전으로 다시 열 수 있습니다. 편집 도중 강제로 새로고침하지 않습니다. 업데이트 버튼이 없는 이전 버전에서 화면이 바뀌지 않으면 아래 복구 페이지를 사용하세요. 브라우저 데이터나 localStorage를 지우지 않아도 됩니다.

### 이전 화면이 계속 보일 때

배포 완료 후 크롬에서 https://easthyeok.github.io/futari/recover.html 을 열어 ‘최신 화면 다시 받기’를 누르세요. 이 페이지는 이전 서비스 워커의 캐시 대상이 아니므로 오래된 앱에서도 새 복구 페이지를 받을 수 있습니다. 다른 futari 탭과 앱 창을 닫고 진행한 뒤 ‘futari 다시 열기’를 누르세요.

복구는 최신 앱 파일을 모두 다운로드하고 배포 버전을 확인한 다음 기존 앱 캐시의 파일을 교체합니다. 방 코드·사용자 선택·localStorage·추억·공유 보드게임 데이터는 삭제하지 않습니다. 미저장 변경이 있으면 복구를 중단하며, 다운로드 실패나 이전 배포가 응답하는 경우에는 기존 캐시를 유지합니다.

설정에서도 ‘이전 화면이 보일 때 새로 받기’로 복구 페이지에 갈 수 있습니다. 페이지가 404이면 해당 파일의 커밋·푸시와 GitHub Pages 배포 완료를 먼저 확인하세요.

## 둘이 보드게임

하단의 독립 보드게임 탭에서 게임을 선택하세요. 게임룸은 게임판 중심 화면, 전체 화면(지원 브라우저), 경기 전적과 최근 결과를 제공합니다. 사목·주사위 레이스·카드 덱은 제거했습니다.

### 오목 · 각자 기기에서 이어하기

15×15 자유 오목입니다. 금수 없이 가로·세로·대각선으로 5개 이상 이으면 승리합니다. 작은 화면에서 실수로 두지 않도록 칸을 선택한 뒤 확인 버튼으로 착수합니다. 판 확대, 좌표, 수 번호, 대국 복기를 지원합니다. 마지막 수는 둔 사람이 요청하고 상대가 동의해야 되돌릴 수 있습니다. 새 경기의 검은 돌·선공은 번갈아 바뀝니다.

오목은 시간제한 없이 방에 저장되어 각자 기기에서 이어합니다. 무르기와 새 판은 상대의 동의가 필요합니다. 다빈치코드와 바운스오프는 제거했으며 기존 백업 속 기록은 보존합니다.

### 총알 피하기 / NEON DRIFT

게임룸에서 총알 피하기를 엽니다. 모바일은 화면 어느 위치에서든 상대적으로 드래그해 기체를 움직이고, PC는 방향키 또는 WASD, Shift로 정밀 이동합니다. 흰 중심점만 피격 판정하며 18초마다 탄막이 강화되고 90초를 버티면 완주합니다. 탄막 예고·근접 회피·효과음 선택을 제공합니다.

연습은 무제한이며 일시정지할 수 있습니다. 실전은 기기 현지 날짜 기준 각자 하루 3번, 최고 생존 시간으로 비교합니다. 같은 날짜·버전은 같은 난수 시드와 고정 시간 간격을 사용합니다. 조준 탄막의 방향은 각자의 이동 위치에 따라 달라집니다. 실전은 시작 시 횟수를 사용하고, 화면 전환·앱 이탈 시 현재 기록으로 종료합니다. 새로고침·비정상 종료 후 남은 예약은 0초로 처리합니다. 기록은 방의 `dodge`에 저장되어 상대 기기와 동기화하며 최근 7일과 역대 최고 기록을 확인할 수 있습니다. 게임 중에는 네트워크 응답을 기다리지 않습니다.

승부는 소수점 둘째 자리까지의 생존 시간만 비교하고 근접 회피 횟수는 승패에 영향을 주지 않습니다. 실전 기록은 기존 방 데이터와 같은 저장 실패·충돌 보호를 따릅니다. 현재 기록은 클라이언트에서 계산하며 서버가 검증하는 대회용 기록은 아닙니다.

### 농장처럼 키우는 우리 마을

메인 화면의 빈 땅을 골라 텃밭·꽃밭·피크닉 자리·사과나무·연못·작업실·온실을 짓습니다. 건설은 현재 잔액을 검사하고 이미 지은 자리에 중복 구매할 수 없습니다. 건물은 무료로 이동·서로 교환할 수 있으며 재배 중인 작물도 함께 이동합니다.

텃밭과 온실에서는 씨앗을 구매해 재배합니다. 래디시 60초, 당근 180초, 딸기 360초이며 온실에서는 두 배 빨리 자랍니다. 각자 한 번 물을 주면 15초씩 단축됩니다. 다 자란 작물은 수확하면 코인이 지급되고, 오랫동안 접속하지 않아도 시들지 않습니다. 중복 수확은 보상하지 않습니다.

집은 오두막 → 농가 → 전원주택 → 꿈꾸던 집의 4단계이며 땅도 4 → 8 → 12 → 16칸으로 늘어납니다. 확장에는 코인과 함께 쌓은 마음이 필요합니다. 집을 누르거나 ‘집 안 꾸미기’에서 기존 가구·벽지·바닥 13종을 구매·배치할 수 있습니다. 실내 가구와 농장은 같은 지갑을 사용합니다. 마을 상태는 `farm`, 실내 소유·배치는 `house`에 저장되어 방 동기화와 백업에 포함됩니다.

오목은 하루 첫 완료에 15 코인을 받습니다. 같은 날 재대결은 중복 보상하지 않습니다. 오늘 우리 카드와 기존 활동에서 얻는 코인, 작물 수확 수입에서 실제 가구·건설·씨앗·확장 비용을 차감해 공동 잔액을 계산합니다.

기존 장소 기록은 백업 호환성을 위해 보존되지만 지도 화면은 제거했습니다.

## 데이터와 동기화

같은 방 코드를 입력하면 Supabase `rooms` 테이블의 데이터를 함께 사용합니다. 기기에는 방 코드가 기억됩니다.
일반 변경은 마지막 입력 후 약 1.2초 뒤 저장하고, 공유 보드게임의 수는 대기 시간 없이 저장을 시작합니다. 상대방의 변경은 보드게임 탭에서는 약 2.5초마다, 나머지 탭에서는 약 10초마다 확인하며 앱으로 돌아왔을 때도 바로 조회합니다. 저장이 완료되기 전에 종료한 변경은 이 기기에 보관됩니다.
저장 실패 메시지를 누르면 다시 시도합니다. 저장하지 못한 변경이 있으면 원격 조회로 덮어쓰지 않습니다.

방 전체 데이터를 저장하며 `updated_at`이 읽었던 버전과 같을 때만 갱신합니다. 상대가 먼저 저장하면 덮어쓰기를 중단하고 오류를 표시합니다. 자동 병합은 지원하지 않습니다. 충돌 시 설정에서 현재 내용을 백업한 후 ‘상대 변경 불러오기’를 눌러 미저장 변경을 버리고 서버 기록을 확인하세요. 실제 Supabase에서 SELECT·UPDATE 정책과 updated_at 컬럼을 확인해야 합니다.
최근 방 데이터와 미저장 변경은 방별로 기기에 보관합니다. 다시 접속하면 최근 화면을 먼저 표시하고 동기화합니다. 서비스 워커가 앱 화면과 정적 파일을 보관해 처음 온라인으로 방문한 뒤에는 오프라인에서도 최근 방 화면을 열 수 있습니다. 새 방 입장과 상대와의 동기화는 인터넷이 필요합니다. 푸시 알림은 아직 지원하지 않습니다.
설정의 백업 내보내기로 데이터를 별도 보관할 수 있습니다. 백업 가져오기는 현재 방의 데이터를 교체합니다.

## 파일

- `index.html`: 화면과 스타일
- `app.js`: React 앱과 공유 저장 로직
- `home.js`: 활동·보상·공동 지갑과 실내 꾸미기
- `farm.js`: 마을 건설·작물·수확·집 확장
- `today.js`: 오늘 우리 카드와 공동 미션
- `dodge.js`: 총알 피하기 시뮬레이션·캔버스·일일 기록 대결
- `board-games.js`: 게임룸·오목·무르기 합의·경기 전적
- `game.css`: 게임룸과 게임판의 전용 디자인
- `manifest.webmanifest`: 설치 이름, 아이콘, 시작 경로
- `pwa.js`: 설치 버튼과 서비스 워커 등록
- `sw.js`: 온라인 파일 갱신과 오프라인 캐시
- `recover.html`, `recovery.js`: 방 정보와 기록을 유지하는 앱 캐시 복구
- `icons/`: 설치 아이콘과 iOS 홈 화면 아이콘
- `config.js`: Supabase 연결 설정
- `vendor/`: 브라우저 라이브러리
- `tests/features.cjs`: 외부 서비스에 연결하지 않는 기능 검증

```sh
node --check sw.js
node --check pwa.js
node tests/pwa.cjs

```

검색·수정·기존 사진 보존·달력·룰렛·공동 활동, 오목 판정·동의 후 무르기·선공 교대·결과 중복 방지, 코인 지급·공동 미션·구매 금액 검증·무료 재배치·보관함·저장 후 복원을 확인합니다.
PWA 검증은 매니페스트·PNG 크기, 루트/하위 경로의 시작 주소, 서비스 워커의 오프라인 응답·캐시 분리, 설치 버튼 이벤트를 확인합니다. 이 검증은 브라우저 렌더링, 실제 크롬 설치 판정이나 Supabase 연결을 대신하지 않습니다.
